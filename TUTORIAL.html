Arquitectura del sistema

OdontoCare es una aplicación multi-tenant. Cada organización puede tener múltiples sedes (clínicas), y cada sede tiene su propio número de WhatsApp.

Prerequisitos

Para desarrollo local

  • Node.js 20+ (node -v)
  • npm 10+ (npm -v)
  • Docker Desktop instalado y corriendo
  • Git
  • Cuenta en supabase.com (gratis)
  • Un teléfono Android o iPhone con WhatsApp

Para producción (VPS)

  • VPS con Ubuntu 22.04 (mínimo 2 GB RAM)
  • Docker + Docker Compose instalados
  • Dominio apuntando al VPS
  • Nginx o Traefik como proxy reverso
  • Cuenta en vercel.com (gratis)
  • Número de WhatsApp dedicado (no tu número personal)
⚠ Sobre el número de WhatsApp Evolution API usa WhatsApp Web (no la API oficial de Meta). El teléfono que vinculés tiene que mantenerse con internet y cargado. Para producción real, usá un número dedicado en un teléfono barato que quede siempre enchufado. La API oficial de Meta requiere verificación empresarial y cuesta dinero.

Supabase — base de datos y autenticación

3.1 Crear el proyecto

1
Ir a supabase.com → New project Elegir región más cercana (South America — São Paulo es la más cercana a Argentina). Anotar la Database password que se genera — la vas a necesitar.
2
Obtener las claves Project Settings → API. Copiar:
• URL → NEXT_PUBLIC_SUPABASE_URL
• anon public key → NEXT_PUBLIC_SUPABASE_ANON_KEY
• service_role key → SUPABASE_SERVICE_KEY (solo backend)
3
Ejecutar la migración inicial Ir a SQL Editor en Supabase Dashboard. Copiar y ejecutar el contenido del archivo: infrastructure/supabase/migrations/001_initial_schema.sql

3.2 Crear el primer usuario

4
Crear usuario en Authentication → Users → Add user Ingresá tu email y una contraseña. Copiá el User UID generado.
5
Crear organización y perfil en SQL Editor Reemplazá los valores y ejecutá: 
-- 1. Crear organización
INSERT INTO organizations (name, slug, plan)
VALUES ('Mi Clínica Dental', 'mi-clinica', 'pro');

-- 2. Obtener el ID recién creado
SELECT id FROM organizations WHERE slug = 'mi-clinica';

-- 3. Crear sede principal
INSERT INTO clinics (organization_id, name, address, phone, whatsapp_number, timezone)
VALUES (
  '<ORG_ID>',
  'Sede Central',
  'Av. Corrientes 1234, CABA',
  '1100000000',
  '5491100000000',  -- formato: 54 + código área + número
  'America/Argentina/Buenos_Aires'
);

-- 4. Crear perfil para el usuario
INSERT INTO profiles (id, organization_id, full_name, role)
VALUES (
  '<USER_UID>',     -- el UID de Supabase Auth
  '<ORG_ID>',
  'Administrador',
  'owner'
);

3.3 Configurar Row Level Security (RLS)

ℹ La migración ya incluye las políticas RLS. Cada usuario solo puede ver los datos de su organización. Si querés verificarlo, andá a Authentication → Policies en el Dashboard.

3.4 Habilitar Email Auth

Authentication → Providers → Email → asegurate de que esté habilitado. Para producción, configurá un SMTP propio en Project Settings → Auth → SMTP Settings (Gmail, Resend, etc.).

Evolution API — conectar número de WhatsApp

4.1 Levantar los servicios con Docker

# Desde la carpeta del proyecto
cd odonto-saas

# Copiar y editar variables (mínimo obligatorio: contraseñas)
cp .env.example .env
notepad .env   # Windows  |  nano .env  en Linux

# Levantar todo
docker compose up -d

# Ver que todos los contenedores estén "healthy"
docker compose ps

Después de ~30 segundos deberías ver:

NAME              STATUS
oc_postgres       running (healthy)
oc_redis          running (healthy)
oc_n8n            running (healthy)
oc_n8n_worker     running
oc_evolution      running

4.2 Crear instancia en Evolution API

Evolution API tiene una interfaz Swagger en http://localhost:8080/docs. Usamos curl para crear la instancia (más rápido):

# Reemplazá YOUR_API_KEY con el valor de EVOLUTION_API_KEY en tu .env
curl -X POST http://localhost:8080/instance/create \
  -H "apikey: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "instanceName": "odontocare",
    "qrcode": true,
    "integration": "WHATSAPP-BAILEYS"
  }'
✓ Respuesta esperada Vas a recibir un JSON con "status": "created" y un QR code en base64. También podés ver el QR en el Dashboard de Evolution.

4.3 Escanear el código QR con tu celular

1
Abrir WhatsApp en el teléfono dedicado Menú (3 puntos) → Dispositivos vinculados → Vincular un dispositivo
2
Obtener el QR desde la API 
curl http://localhost:8080/instance/connect/odontocare \
  -H "apikey: YOUR_API_KEY"
La respuesta tiene un campo "base64". Pegá ese valor en base64.guru para ver la imagen del QR, o usá el Dashboard de Evolution en http://localhost:8080/manager.
3
Escanear el QR con la cámara del teléfono Una vez escaneado, el estado de la instancia pasa a "open". Verificar: 
curl http://localhost:8080/instance/fetchInstances \
  -H "apikey: YOUR_API_KEY"
# Buscar: "connectionStatus": "open"

4.4 Configurar el webhook

Le decimos a Evolution API que mande los mensajes entrantes a nuestra app:

curl -X POST http://localhost:8080/webhook/set/odontocare \
  -H "apikey: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "http://host.docker.internal:3000/api/webhooks/whatsapp",
    "webhook_by_events": false,
    "webhook_base64": false,
    "events": ["MESSAGES_UPSERT"]
  }'
ℹ host.docker.internal Es la dirección que usa Docker para acceder al localhost del host. En producción reemplazás por la URL real de tu app: https://tu-app.vercel.app/api/webhooks/whatsapp

4.5 Probar que el bot responde

Mandá un mensaje de otro celular al número vinculado. En los logs de tu app deberías ver la petición entrante:

# Tail de logs de la app (una vez levantada con npm run dev)
npm run dev
# En otra terminal, mirá los logs de Evolution:
docker compose logs -f evolution

4.6 Agregar múltiples sedes con distintos números

Cada sede puede tener su propia instancia. Repetí los pasos 4.2 y 4.3 con otro nombre de instancia:

# Instancia para "Sede Norte"
curl -X POST http://localhost:8080/instance/create \
  -H "apikey: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "instanceName": "odontocare-norte",
    "qrcode": true,
    "integration": "WHATSAPP-BAILEYS"
  }'

En la base de datos, actualizás el campo whatsapp_number de cada clínica con el número correspondiente, y en el código el bot busca qué instancia usar según la sede activa.

App Password de Gmail

Si usás Gmail para enviar emails: myaccount.google.com → Seguridad → Verificación en 2 pasos → Contraseñas de aplicaciones. Generás una contraseña de 16 caracteres para "Correo" y la usás como SMTP_PASS.

Deploy en Vercel (producción)

1
Instalar Vercel CLI 
npm install -g vercel
2
Login y linkear el proyecto 
cd odonto-saas
vercel login
vercel link
3
Cargar los secrets de Vercel El vercel.json referencia @nombre_secret. Cargarlos así: 
vercel secrets add supabase_url "https://tu-project.supabase.co"
vercel secrets add supabase_anon_key "eyJ..."
vercel secrets add evolution_api_url "https://tu-vps.com:8080"
vercel secrets add evolution_api_key "tu-api-key"
vercel secrets add evolution_instance "odontocare"
vercel secrets add app_url "https://tu-app.vercel.app"
vercel secrets add n8n_webhook_base_url "https://tu-vps.com:5678/webhook"
4
Deploy 
vercel --prod
# O conectar el repo de GitHub para auto-deploy en cada push
5
Actualizar el webhook de Evolution API Una vez deployado, actualizar la URL del webhook con la URL real de Vercel: 
curl -X POST https://tu-vps.com:8080/webhook/set/odontocare \
  -H "apikey: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://tu-app.vercel.app/api/webhooks/whatsapp",
    "events": ["MESSAGES_UPSERT"]
  }'
⚠ Docker en producción El docker-compose.yml es para n8n y Evolution API que corren en un VPS (no en Vercel). Vercel solo hostea la app Next.js. Los servicios de Docker necesitan un VPS con IP pública y dominio, o podés usar servicios cloud:
• n8n: n8n.cloud (tienen plan gratuito limitado)
• Evolution API: necesita sí o sí un servidor propio por la conexión de WhatsApp Web

Troubleshooting frecuente

❌ "La app carga pero no hay datos reales"

Falta el archivo .env.local o las variables de Supabase están mal. Verificar que NEXT_PUBLIC_SUPABASE_URL y NEXT_PUBLIC_SUPABASE_ANON_KEY estén correctas. La app funciona en modo demo sin Supabase.

❌ "Error al hacer login: invalid credentials"

El usuario debe existir en Supabase Authentication AND en la tabla profiles. Si está en Auth pero no en profiles, el login funciona pero la app no carga el perfil. Verificar con el SQL del paso 3.2.

❌ "Evolution API status: close (no conectado)"

El QR expiró o la sesión de WhatsApp Web se cerró. Reconectar:

curl -X DELETE http://localhost:8080/instance/logout/odontocare -H "apikey: TU_KEY"
curl http://localhost:8080/instance/connect/odontocare -H "apikey: TU_KEY"
# Escanear QR nuevamente

❌ "El bot no responde a mensajes"

  1. Verificar que el webhook de Evolution esté configurado con la URL correcta
  2. Verificar que Next.js esté corriendo (npm run dev)
  3. Ver los logs: docker compose logs evolution
  4. Verificar en Evolution que la instancia está en estado "open"
  5. El bot ignora mensajes del propio número (campo fromMe: true)

❌ "n8n workflows no se activan"

Verificar que los workflows estén con toggle ON. Para los de tipo webhook, la URL que n8n genera debe ser accesible desde Evolution API. Si ambos corren en Docker, usar el nombre del servicio: http://n8n:5678/webhook/...

❌ "Build de Next.js falla"

# Limpiar cache y reinstalar
rm -rf .next node_modules
npm install
npm run build

❌ "WhatsApp se desconecta solo"

WhatsApp Web cierra la sesión si el teléfono no tiene internet o si WhatsApp detecta actividad inusual. Soluciones:

  • Usar un teléfono dedicado siempre encendido y conectado a WiFi
  • Activar keepAliveIntervalMs en la configuración de la instancia de Evolution
  • Configurar alertas para cuando el estado pase a "close" (workflow 11 puede adaptarse para esto)
✓ Sistema completo Con todos estos pasos configurados, OdontoCare corre con: autenticación real por Supabase, bot de WhatsApp activo, 15 automatizaciones de n8n funcionando, y la app deployada en Vercel. El modo demo siempre está disponible para mostrarle la plataforma a un cliente sin necesidad de conectar nada.
